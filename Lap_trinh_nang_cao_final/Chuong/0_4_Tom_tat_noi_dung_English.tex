\begin{center}\bfseries\large ABSTRACT\end{center}
\vspace{0.5cm}
The project starts from instructors' need to find and book classrooms for teaching, meetings, and other academic activities. Room information and schedules are currently managed mainly in Excel files, so checking availability, capacity, equipment, and submitting requests still involves manual work. RoomHub digitises the room search, booking, approval, notification, and access-permission workflow for instructors and administrators. In this pre-MVP scope, the team models and tests the system in an eight-storey building with a room layout similar to Building C7 at Hanoi University of Science and Technology; deployment across the whole campus is outside the current scope.

The scope narrows from shared-room resource management to a specific Android classroom and meeting-room booking system, RoomHub. Its implemented system includes a React Native/TypeScript client, a Java 17/Spring Boot backend exposing REST APIs, and an H2 database accessed through JPA. Remote mode is enabled in the current source: the client reads and writes business data through the backend. Local Async Storage remains available as a separate mode; offline local changes are not automatically reconciled with the server. The configured public tunnel is for testing and does not represent production availability.

For rooms equipped with a smart lock, an administrator or an authorised user may create a seven-digit temporary PIN. The application records the PIN and its validity interval before attempting delivery. Once a OneIoT session is connected, the mobile client publishes the corresponding MQTT message. Broker publication is not treated as proof that the physical lock has applied the PIN. Automated application tests and Java integration tests are present; a release build has also been checked on an Android device in local mode. End-to-end availability of the remote server and multi-device data sharing still depend on a running backend, database and reachable API endpoint.
